# exp2 阶段性结论与下一步精度补偿方案（2026-04-04）

## 0. 结论先行（严格对应你的目标）

你的核心目标是：在保持 MBV3 轻量化优势的同时，使改进模型在 **Recall 与 mAP50-95** 上也超过 baseline。

基于当前可复核结果，三次改进都未完成该目标，且失败模式高度一致：

- `mbv3_eca`：相对 `mbv3` 仅小幅回升 Recall，但 mAP50-95 明显下降，补偿方向偏离主目标。
- `mbv3_p2_simam`：Precision 明显升高，但 Recall 与 mAP50-95 下滑更严重，出现“高置信度保守预测”问题。
- `mbv3_p2`：比 `p2_simam` 明显更健康（去掉 SimAM 后 R/mAP 恢复、FPS 回升），但仍未超过 baseline 的 Recall 与 mAP50-95。

因此，当前证据支持的判断是：

1. 主要瓶颈不是“是否再加一个注意力模块”，而是轻量 backbone 下的多尺度信息保真与长尾类召回。
2. 在该数据集上，P2 不是“万能补偿”，但可以作为补充手段；真正决定上限的是融合策略与训练目标（召回导向）是否匹配。
3. 若暂不做蒸馏，最佳路线应是“**P2 保留 + Neck 轻量双向融合 + 召回导向训练重配 + 最小化注意力**”，而不是继续堆叠通道注意力。

## 2. 数据集特征与任务难点（来自 exp1/dataset 的实测统计）

### 2.1 数据规模与类别结构

- 总样本对：6652，划分 4656/997/999。
- `nc=10`，但 `split_stats.json` 的分类计数里未出现类别 `3`（Lambsquarters），说明当前训练口径下该类有效实例缺失。
- 类别长尾明显：训练集中最大类（id=9）约 2018，最小类（id=1）约 200，约 10:1。

### 2.2 目标尺度分布（按归一化框面积统计）

以训练集为例（7800 个框）：

- 小目标（面积 < 1%）：10.4%
- 中目标（1%~9%）：37.9%
- 大目标（>=9%）：51.7%
- 中位面积约 9.5%

这说明：数据集并非“极端小目标主导”，而是 **中大目标占主导 + 存在少量难检小目标 + 明显长尾**。

### 2.3 对结构改造的直接启示

1. 仅靠 P2 并不会自动提升整体 Recall，因为主分布不是纯小目标。
2. 长尾类召回与中高 IoU 定位质量（mAP50-95）更依赖融合质量与损失权重，而非单点注意力。
3. 当模型倾向“更保守高置信”时，会先抬 Precision，再伤 Recall，这正是你当前实验的共同模式。

## 3. 三次改进失败原因的结构化诊断

## 3.1 `mbv3_eca` 失败原因

### 3.1.1 结构层面：补偿点选错

`mbv3_eca` 在 P3/P4/P5 全插 ECA，属于 Backbone 侧通道重标定。

问题在于：

- MBV3 轻量 backbone 已经压缩了表示冗余，再做全尺度通道门控，容易牺牲弱响应目标。
- Neck 融合机制并未实质加强，无法把“被压弱的细节”在跨尺度融合中找回来。

对应指标：Recall 比 mbv3 略有回升（+0.0046），但 mAP50-95 明显下降（-0.0086，vs mbv3），说明定位质量与高 IoU 区间性能受损。

### 3.1.2 任务匹配层面：未命中主矛盾

你的主矛盾是 Recall 与 mAP50-95 不足；ECA 主要改变通道权重分配，不直接增强多尺度几何定位能力。

所以它可能“轻微修复分类置信”，但无法稳定补偿中高 IoU 指标。

---

## 3.2 `mbv3_p2_simam` 失败原因

### 3.2.1 结构耦合效应：P2 + SimAM 把模型推向“保守判定”

`p2_simam` 在高分辨率路径上加入 SimAM。该模块虽无参数，但会按空间统计对神经元响应进行抑扬。

在你的任务上表现为：

- 更少误检 -> Precision 升高（0.9526）
- 更多漏检 -> Recall 降低（0.8890）
- 综合定位质量下降 -> mAP50-95 降至 0.8760

这是典型的“过度置信筛选”副作用。

### 3.2.2 计算与部署层面：无参数不等于低时延

虽然 SimAM 无可训练参数，但包含多次逐元素与统计运算，容易造成算子碎片化与内存访问开销。

从结果看：

- 与 `a1_p2` 相同参数规模（7.607M），但 FPS 从 44.42 掉到 36.83。
- 说明速度下降主要来自算子执行路径，而不是参数量。

### 3.2.3 训练完整性层面：177 轮带来不确定性

`p2_simam` 未满 200 轮，不排除后续还能恢复部分 Recall；但从现有曲线与最终评测看，其方向性问题（高 P、低 R）已较明确。

---

## 3.3 `mbv3_p2`（a1_p2）为什么仍未完成补偿

`a1_p2` 是非常关键的对照：

- 去掉 SimAM 后，Recall 从 0.8890 回升到 0.9046，mAP50-95 从 0.8760 回升到 0.8853，FPS 也恢复到 44.42。
- 这基本确认了“SimAM 插入策略”是 p2_simam 失败主因之一。

但 `a1_p2` 仍落后 baseline：

- Recall 低 0.0161
- mAP50-95 低 0.0074

说明单加 P2 仍不足以完成补偿，核心缺口在：

1. 跨尺度融合质量不足（尤其中高 IoU 下的定位一致性）。
2. 长尾类召回缺口未被训练目标显式优化。
3. 当前训练超参对“高精度保守预测”有偏好，缺乏召回导向重配。

---

## 4. 归纳：三次失败的共同根因

1. **方向性偏差**：改动更偏向降低误检（Precision）而非降低漏检（Recall）。
2. **补偿位置偏差**：Backbone 端注意力强于 Neck 融合改造，未命中 mAP50-95 短板。
3. **数据匹配偏差**：数据并非纯小目标主导，单纯 P2 不能解决全局问题。
4. **长尾约束未处理**：类别极不均衡 + 缺失类现象，召回天然受压。
5. **训练目标未对齐**：尚未建立“召回优先”的损失与样本策略闭环。

## 5. 任务2：最佳改进方案（不考虑蒸馏）

## 5.1 推荐主方案（优先执行）

方案名：**MBV3-P2-BiFPNlite-RecallBalanced（无 SimAM/ECA）**

### 5.1.1 结构设计

1. 保留 MBV3 主干（维持轻量化基础）。
2. 保留 P2 检测头（作为小目标补充通道）。
3. 移除 SimAM 与全尺度 ECA（先避免保守门控副作用）。
4. 将现有 PAN/FPN 融合改为轻量 BiFPN-Lite（可学习融合权重，深度可分离卷积实现）。
5. Detect 头保持单阶段解耦，不额外叠加复杂注意力。

### 5.1.2 训练策略（与结构同等重要）

在公平协议框架内，做“召回导向微调”而非大改：

- 分类损失与框损失比例向 Recall 轻微倾斜（小步调整，避免 Precision 崩塌）。
- 对长尾类做温和重加权或重采样（建议上限 1.5x，防止过拟合）。
- 适度降低强增强后期强度（close_mosaic 可提前，减少定位噪声）。
- 推理阈值进行校准（统一在验证集上选择兼顾 P/R 的 operating point）。

### 5.1.3 可行性判断

- 工程可行：在你当前 exp2 框架可实现，不依赖新外部大模块。
- 风险可控：先去除已证伪模块（SimAM 全局插入），再引入单一融合改造，变量可控。
- 与数据集匹配：BiFPN-Lite 主要改善多尺度融合一致性，正对 mAP50-95 与 Recall 短板。

### 5.1.4 预期收益（谨慎区间）

相对当前 `a1_p2`，合理预期：

- Recall：+0.8 ~ +1.8 个百分点
- mAP50-95：+0.4 ~ +1.2 个百分点
- Params：增加可控（建议 <= +8%）
- FPS：维持在 `mbv3` 的 90% 以上为可接受

> 注：区间是基于当前任务数据分布和已有失败模式推断，不应写成确定性结论，需实验验证。

## 5.2 备选方案 A（更稳健，改动小）

方案名：**MBV3-P2 + Neck 单点轻注意力（仅 1 处）**

- 不在 Backbone 放注意力。
- 仅在 P3/P4 融合后选择 1 处插入轻注意力（可先试 SimAM/NAM 二选一）。
- 目标是局部增强而不改变整体判定风格。

可行性：改动最小，训练风险低。

风险：收益可能低于 BiFPN 路线，容易“略有提升但不够跨越 baseline”。

适用：当你希望先拿一个高成功率小改版本作为论文中“过渡性正结果”。

---

## 5.3 备选方案 B（召回优先训练方案）

方案名：**MBV3-P2 + Recall-First Training（结构不变）**

核心思路：先不改结构，仅重配训练目标与采样。

- 长尾类 reweight / resample。
- 对易漏检类做困难样本回放。
- 验证集上做阈值与 NMS 超参联合校准。

可行性：实现最快，能直接验证“是否主要是训练目标问题”。

风险：上限可能不如结构改造，且可能牺牲 Precision。

适用：作为主方案前的低成本先验试验（建议先跑 100 epoch 快速筛）。

---

## 6. 推荐执行顺序（最小试错成本）

1. 以 `a1_p2` 为新对照起点，冻结为 Stage-A baseline。
2. 先跑“训练重配小网格”（不改结构，100 epoch 快筛），验证 Recall 是否可被拉起。
3. 若有增益，再上 BiFPN-Lite（主方案），跑满 200 epoch。
4. 若 BiFPN 提升不足，再试“Neck 单点轻注意力”而不是全尺度注意力。
5. 所有候选统一同口径评估：`iou=0.7, max_det=300`，并输出 full JSON + results.csv。

## 7. 论文写作建议（可直接引用）

1. 已验证“注意力堆叠并不等价于精度补偿”，在本任务中会诱发高精度低召回现象。
2. `p2_simam` 的失败不是单因素，包含模块插入策略、运行时算子开销和训练未满轮三重影响。
3. `a1_p2` 证明“移除不当注意力后可恢复部分性能”，为后续融合层改造提供了更干净起点。
4. 下一阶段应从“Backbone 加门控”转向“Neck 融合增强 + 召回导向训练”的协同优化。
