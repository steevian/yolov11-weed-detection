# 原单类杂草检测系统升级为多类别检测（最小改动方案）

## 0. 目标与约束

目标：在保持 Flask + Vue 原架构、原页面、原流程不变的前提下，将原单类检测升级为多类别检测，并同时覆盖三个功能：
1. 图像检测：上传图片 -> 多类别检测 -> 显示类别名 + 检测框
2. 视频检测：上传视频 -> 逐帧多类别检测 -> 显示类别名 + 检测框
3. 实时摄像头检测：开启摄像头 -> 实时多类别检测 -> 显示类别名 + 检测框

严格约束：
- 不重构原逻辑，不新增页面，不改变接口整体结构。
- 只做必要最小改动：模型路径替换、类别信息适配、前端类别名显示。
- 杂草类别名统一使用中文。
- 全流程避免中文乱码（文件编码统一 UTF-8）。

## 1. 现状调查结论（已确认）

1) 后端统一模型入口
- 文件：yolo_weed_detection_flask/main.py
- 当前固定模型文件名：weed_best.pt
- 模型在 VideoProcessingApp 初始化时预加载，并被图像/视频/摄像头三类检测共用。

2) 三个检测功能当前实现
- 图像检测：/predict 与 /predictImg -> predictImg()
- 视频检测：/predictVideo + WebSocket process_video
- 摄像头检测：/predictCamera /stopCamera

3) 前端显示链路
- 图像页：已支持 detections 表格 + canvas 绘制框 + 文本标签。
- 视频页：展示后端输出视频（检测框和标签由后端 plot 渲染到帧内）。
- 摄像头页：展示后端 MJPEG 实时流（检测框和标签由后端 plot 渲染到帧内）。

4) 潜在风险点
- 当前模型类名大概率是英文（训练配置为英文类名），若不映射，前端/视频叠字会显示英文。
- 视频和摄像头的标签来自 YOLO plot，必须在后端模型 names 层做中文化，才能同步变成中文。

## 7.  本次问题与根因

### 7.1 Flask 启动失败根因
启动 `yolo_weed_detection_flask/main.py` 时出现两类错误：
1. `No module named 'ultralytics.nn.modules.eca'`
2. `property 'names' of 'YOLO' object has no setter`

根因分析：
1. 新模型 `eca2-1.pt` 依赖 ECA 自定义模块，而默认 pip 版 `ultralytics` 不包含 `ultralytics.nn.modules.eca`。
2. `YOLO.names` 在当前版本中为只读属性，不能直接赋值。

## 13. 五次修复增量（原始视频404专项）

### 13.1 现象
1. 原始视频请求大量 `GET /uploads/detect/videos/*.mp4 404`。
2. 结果视频可播放，说明问题集中在原视频静态访问链路。

### 13.2 修复
1. 后端新增 Flask 前缀静态路由：
	- `/flask/uploads/<path:filename>`
	- `/flask/results/<path:filename>`
	- `/flask/runs/<path:filename>`
2. 前端原视频地址改为优先映射到 `/flask/uploads/...`，避免依赖 `/uploads` 代理是否存在。
3. 后端 `serve_upload` 增加历史目录兜底：
	- 先查 `yolo_weed_detection_flask/uploads`
	- 不存在则回退 `项目根目录/uploads`

### 13.3 验证
1. `/flask/uploads/detect/videos/<file>.mp4` 返回 200，`Content-Type: video/mp4`。
2. `/uploads/detect/videos/<file>.mp4` 同样可返回 200（兼容保留）。
3. 前端构建通过，原视频播放器可恢复正常控件渲染与交互。

## 14. 六次修复增量（原始视频编码兼容）

### 14.1 问题
原始视频存在“有声音、有进度条，但画面黑屏”的情况，定位为浏览器对部分原始编码不兼容。

### 14.2 修复
1. 在后端上传接口 `upload_file` 中，对所有上传视频执行强制转码：
	- 视频编码：`H.264 (libx264)`
	- 音频编码：`AAC`
	- 像素格式：`yuv420p`
	- 启动优化：`+faststart`
2. 转码成功后仅保留转码后的 `.mp4`，并返回该文件访问路径给前端。
3. 转码失败时直接返回错误，不再把不兼容源视频写入业务链路。

### 14.3 结果
原始视频统一为浏览器兼容编码，历史页播放器可稳定显示画面与声音。
